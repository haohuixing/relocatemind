## 1. PROJECT OVERVIEW & TECH STACK

**RelocateMind** is a Product-Led Growth (PLG) global mobility engine that matches users with digital nomad and residency visa programs based on their passport country, monthly revenue ($USD), and income source.

* **Backend Framework**: Python 3.10+, FastAPI (ASGI, Asynchronous routing)
* **ORM & Database**: SQLAlchemy (Declarative Base) + SQLite (`relocation.db`)
* **Auth & Session Security**: 
  - PBKDF2-SHA256 password hashing via `passlib`
  - Stateless HMAC-SHA256 signed HTTP-only cookies (`session_token` and `anon_test_data`)
* **Templating**: Jinja2 + Starlette `Jinja2Templates` (Explicit modern Starlette 0.28+ signature: `request=request, name="..."`)
* **Frontend Aesthetic**: Pure Tailwind CSS (via CDN), Inter & JetBrains Mono fonts, Glassmorphic Raycast/Linear/Vercel dark mode theme (`bg-slate-950`), GPU-accelerated CSS micro-animations.
* **Localization (i18n)**: All UI copy, labels, button text, and messages MUST be pulled from `locales/en.json` via the Jinja helper `{{ t('key.path') }}` defined in `app/core/i18n.py`.

## 3. USER JOURNEY ARCHITECTURE (PLG Funnel)

The app supports two distinct state-handling user journeys:

### PATH A (Direct Account Creation):
1. User visits `/` (Homepage).
2. Clicks "Create Account" -> `GET /register`.
3. Submits registration -> `POST /register` creates `User` & default `UserProfile`.
4. Redirects to `/dashboard` with session cookie.

### PATH B (PLG Anonymous Match to Account Conversion):
1. User visits `/` (Homepage) -> Clicks "Take Free Test" (`GET /free-test`).
2. Fills out passport, income, and income source -> Submits `POST /match`.
3. `matcher.py` runs hard eligibility checks & purchasing ratio algorithms.
4. Input fields & computed match results are packed into a JSON string, HMAC-signed, and saved into an HTTP-only cookie (`anon_test_data`).
5. Redirects to `GET /results` (renders matches + CTA banner "Create Account to Save My Plan").
6. User clicks CTA -> `GET /register` (detects `anon_test_data` cookie and displays a pre-populated banner).
7. User completes registration -> `POST /register` extracts `anon_test_data` cookie, populates `UserProfile` with test data & matches, deletes `anon_test_data`, issues `session_token`, and redirects to `/dashboard`.
